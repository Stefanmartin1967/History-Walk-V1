- SCOUT : RÉOUVERTURE AUTO APRÈS CRÉATION D'UNE DESTINATION (retour Stefan, v3.7.271) — suite du flux inversé v2 (#834) : devoir relancer le Scout à la main sur le brouillon qu'on vient de créer était une friction. Le reload de bascule reste inévitable (changer de destination = reboot complet de Heripia), mais le Scout se rouvre désormais DESSUS automatiquement. `createDestinationDraft` (scout.js) bascule en `?map={id}&scout=1` ; main.js lit `?scout=1` (même patron que `?poi=`/`?import=` : URL nettoyée via replaceState + délai 500 ms pour laisser la carte finir) et rappelle `startScout()`. Desktop + admin only (le Scout n'existe pas sur mobile ; `startScout` regarde de toute façon `state.isAdmin`/`currentMapId`) ; échec d'import dynamique → warn, pas de crash. Toast de création reformulé (« le Scout rouvre dessus » au lieu de « relance le Scout »). Vérifié en preview : création Hammamet → bascule → Scout rouvert seul sur le brouillon vide (statut « brouillon local »), URL nettoyée, prêt à tracer/scanner.

(2) LE SCOUT MOISSONNE TOUJOURS LA DESTINATION ACTIVE — chemin de capture unique via addPoiFeature → `customPois_{id}`, le canal canonique lu par la publication (cf. en-tête publish-destination.js : le snapshot draftGeoJSON_{id} n'est écrit qu'à la création) ; autant de passes de scan/capture qu'on veut.
